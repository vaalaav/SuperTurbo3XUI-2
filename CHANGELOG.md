### Added

- Ежедневное обновление geo-файлов таймером `3xui-node-geo-update.timer` с проверкой, что правила шаблона находят свои категории; зеркало для Happ синхронизируется из файлов панели.
- Проверка geo-правил шаблона Xray через `/panel/api/xray/geodata/validate` перед сохранением.
- Проверка туннеля Psiphon перед добавлением маршрутов; `PSIPHON_STATUS` в `state.env`; проверки Psiphon и таймера geo-файлов в `my3xui audit`.
- Сквозной сценарий `psiphon` в CI.
- CI на GitHub Actions: shellcheck, ruff, actionlint, gitleaks, модульные тесты, сквозные сценарии модуля 05 на чистой машине и проверка конфигурации nginx (`tests/`, `.github/workflows/ci.yml`).
- Флаг `install.sh --xui-version <тег>` и переменная `XUI_VERSION` в `state.env`: версия 3x-ui фиксируется тегом релиза (по умолчанию `v3.11.0`), неподходящий формат или версия ниже `v3.11.0` отклоняются сразу.
- Обновление 3x-ui ниже 3.11.0 модулем 05 с предварительным бэкапом `/etc/x-ui` в `/root/3xui-node-backups/`.
- Постоянный именованный API-токен панели `3xui-node` (`XUI_API_TOKEN` в `state.env`), который перевыпускается только при отказе панели.
- Вопрос мастера про лимит устройств на клиента (IP Limit 3x-ui, jail `3x-ipl`), переменная `ENABLE_IP_LIMIT`.
- Проверка после рестарта Xray, что он устойчиво запущен, и проверка ссылок клиента, которые отдаёт панель (домен:443, UUID, security, flow).
- Разделы README: параметры `install.sh`, версия 3x-ui, API-токен, устранение неполадок, известные ограничения.

### Changed

- Шаблон Xray строится поверх встроенного шаблона установленной 3x-ui (RoutingService, metrics, inbound `tunnel`, `finalRules`); предпочтение IPv4 для `direct` задаётся через `streamSettings.sockopt.domainStrategy` вместо устаревшего `freedom.domainStrategy`.
- Geo-файлы при установке обновляются штатным механизмом панели (все шесть, со сверкой дайджестов) вместо прямой загрузки RU-наборов `curl` без проверки.
- Psiphon ставится установщиком vps-psiphon, закреплённым по коммиту и sha256, с образом, закреплённым по digest; SOCKS5 только на `127.0.0.1`; Docker — пакет `docker.io` дистрибутива вместо `get.docker.com | sh`.
- Socks-аутбаунд `psiphon-out` в современной форме (`address`/`port`).
- Итог модуля 06 перечисляет реально применённые выходы; в режиме `none` модуль снимает оставшиеся маршруты AI-выходов вместо пропуска.
- `my3xui clean` удаляет Psiphon через `vps-psiphon uninstall`.
- 3x-ui устанавливается официальным установщиком выбранного релиза в штатном неинтерактивном режиме (`XUI_NONINTERACTIVE`, `XUI_*`); вывод установщика пишется в `/var/log/3xui-node-xui-install.log` с правами 600.
- Настройки панели задаются её CLI (`setting -listenIP`, `cert -reset`) вместо прямой записи в SQLite.
- Вход в API по паролю (запасной путь) идёт через штатный `/csrf-token` 3x-ui 3.11.
- Шаблон Xray читается и сохраняется через `/panel/api/xray/` и `/panel/api/xray/update`; пользовательские маршруты (AI-модуль) переносятся при повторном запуске модуля 05.
- WARP-аутбаунд использует пользовательский TUN (`noKernelTun`) и `ForceIPv4v6`, как встроенный WARP панели.
- `my3xui clean` удаляет файлы, которые ставит официальный установщик 3x-ui.

### Fixed

- Режим Psiphon не работал: модуль собирал Docker-образ из репозитория vps-psiphon, где никогда не было `Dockerfile`, и передавал несуществующий флаг `--socks-listen`.
- Модули 05, 06 и 07 ждут, пока панель начнёт отвечать после перезапуска `x-ui`: раньше следующий шаг мог обратиться к API раньше, чем панель открывала порт (найдено сквозным тестом в CI).
- Тексты подтверждения в `my3xui clean` выводились кракозябрами (двойная кодировка UTF-8/CP1251).
- Ошибка запроса рестарта Xray больше не теряется молча.
- Ответы API `success:false` больше не проходят молча.
- UUID клиента передаётся в поле `id`: раньше панель генерировала свой UUID, и ссылки в `/root/vps-credentials.txt` не работали.
- Хосты передаются массивами `hosts`/`alpn`: раньше XHTTP рекламировался в подписке как loopback-порт 11443 без TLS.
- Клиент удаляется по email, повторный запуск модуля 05 не оставляет клиентов-сирот.
- AI-модуль реально применяет маршруты WARP/Psiphon (раньше шаблон писался в поле, которое 3.11 игнорирует).
- `proxy_http_version 1.1` для XHTTP в Nginx: значение `2` Nginx отклонял, и модуль 07 откатывал конфигурацию.
- Значения передаются в `xui_api.py` в форме `--опция=значение`: ключ Reality или пароль, начинающийся с `-`, ломал модуль 05 примерно в 3% установок.

### Removed

- Повторная сборка шаблона Xray в `xui_v311_post.py` — шаблон собирается в одном месте.
- Самодельная обвязка CSRF с разбором HTML страницы панели.
- Несуществующие в 3.11 ключи настроек `subHappRouting`, `happRouting`, `subIncyRouting`, `subShowInfo`.
